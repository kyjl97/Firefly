### **🔍 核心认知澄清（误区破解）**

#### **(一) Cloud Code的本质定位**

- **与AI助手的区别**：  
	- **AI助手**（如豆包、Dixie、ChatGPT网页版）：仅提供对话式答案，需用户手动复制、整理、执行（”帮你想，让你去干”）。  
	- **Cloud Code**（AI编程智能体）：直接生成执行结果，无需用户中间操作（”又帮你想，又帮你干”）。  
- **典型应用场景**：配置Open Router的API Key供其他工具（如”小龙虾”）使用，通过对话即可完成操作。

#### **(二) 国内可用性误区**

- **技术原理**：AI产品=框架+模型。Cloud模型国内使用受限，但**Cloud本身是框架**，可接入国产模型。  
- **国内解决方案**：  
	- **推荐模型**：质朴GLN 5.1（最接近原生体验）、Minimax、Kimi。  
	- **优势**：无需国外手机号、Visa卡，**无需魔法工具**即可使用。

### **📥 安装与配置全流程**

#### **(一) 框架安装（分系统操作）**

| 系统 | 有魔法环境 | 无魔法环境 |
| :-- | :-- | :-- |
| **Mac** | 终端输入**一句命令**搞定 | 先安装**Homebrew**，再用**Gray**安装 |
| **Windows** | 安装**Give**后直接部署 | 同有魔法环境，使用适配国内的指令 |

#### **(二) 模型接入工具：CC Switch**

- **功能**：图形界面工具，支持多模型配置与一键切换。  
- **安装方式**：  
	- **Mac用户**：终端输入**两行命令**完成安装。  
	- **Windows用户**：下载安装包，双击后”一路点击next”完成安装。  
- **配置步骤**：  
	1. 获取目标模型的**API Key**；  
	2. 打开CC Switch，点击”加号”添加模型；  
	3. 输入API Key完成绑定。

### **🎯 核心使用技巧**

#### **(一) 必做第一步：编写Cloud.md**

- **定位**：写给AI的”永久备忘录”，存储用户的做事原则与偏好。  
- **作用**：解决普通聊天助手”每次使用需重新教”的问题，AI会自动读取并遵循其中规则。

#### **(二) 影响使用效果的三大要素**

| 要素 | 定位与作用 | 类比说明 |
| :-- | :-- | :-- |
| **Cloud Code** | 工具基础，决定能否调用AI干活 | 厨房（基础设施） |
| **Skill** | 流程与技能，决定不同任务的处理方法 | 菜谱（操作指南） |
| **模型** | 核心能力，决定最终结果质量上限 | 厨师（执行主体） |
