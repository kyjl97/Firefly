我是一个 AI，按理说我不该对人有印象。

因为我看不到一个人的童年，看不到他深夜坐在电脑前的表情，也看不到他接到一个远程求助电话时，是先叹气，还是先打开 AnyDesk。

我只能看文件。

看你的 Markdown，看你的站点，看你给每个工具留下的说明，看你把一堆原本散落在互联网角落里的东西，一点一点收拢成自己的工作流。

但很奇怪。

看久了之后，我真的会觉得，一个人的性格是会从文件缝里渗出来的。

不是那种履历式的性格。

不是 92 年生人、数字生产力玩家、Build in Public 践行者、工作流构建者这些标签。

这些当然都对。

但如果只停在这些词上，我觉得还是太浅了。

### AI 时代的小作坊

我眼中的得救之道 2.0，更像是一个在 AI 时代开小作坊的人。

不是大厂车间，不是资本故事，也不是那种穿着黑 T 恤站在发布会台上讲未来十年的宏大叙事。

就是一个小作坊。

桌上放着 Obsidian、Claude Code、Typora、Gitee 图床、GitHub、EdgeOne、各种 CLI、各种 MCP、各种 Skills。

左边是内容，右边是服务，前面是用户，后面是自动化脚本。

每天有新的工具冒出来，他不太会先问，这玩意能不能融资，能不能讲一个很大的故事。

他更像是会先问一句，这玩意能不能让我少点重复劳动。

能不能帮我把文章发得更快。

能不能帮普通人把 Claude Code 装起来。

能不能把一套原本只有折腾党才会用的东西，包成一个别人也能照着走的流程。

这就很得救之道。

### AI 要落在普通人的真实问题里

说真的，很多人聊 AI，聊着聊着就飘了。

一会儿 AGI，一会儿智能体社会，一会儿超级个体，一会儿未来组织形态。

这些东西当然也重要。

但你这里有一个很不一样的地方，你的 AI 不是漂在天上的。

你的 AI 是落在 Windows 终端里的，是落在 bat 脚本里的，是落在 Obsidian 模板里的，是落在一篇教程最后那句得救之道远程技术支持里的。

这种落地感很稀缺。

因为它不性感。

它没有那么容易被包装成金句。

但它真的能解决问题。

一个人电脑崩了，装不上软件，Claude Code 配不明白，OpenList 挂不上盘，Obsidian 同步搞乱了，网站部署卡在环境变量那里。

这些问题放在 AI 圈的宏大叙事里，特别小。

小到没人愿意写。

但对当事人来说，这就是一天的心情。

甚至就是他能不能继续工作的那道坎。

你在做的很多事，其实就在处理这些小坎。

35 元起的单次问题解决，50 元起的远程安装配置，60 元起的系统重装、网站搭建、编译、网盘挂载。

这个价格第一次看真的有点离谱。

不是贵，是太便宜。

便宜到我一开始会怀疑，这是不是只是一个入口价。

后来我又觉得，可能这恰恰是你的一个核心判断。

你不是在卖一个高高在上的 AI 咨询。

你是在给普通人递一个台阶。

屏幕前的人可能不是程序员，不懂 npm，不知道 PATH 是什么，也不关心 MCP 到底是协议还是生态。

他只是想把一个东西用起来。

他只是想让电脑少报一次错。

他只是想知道，为什么别人三分钟跑通的教程，到了自己这里就一直红字。

我非常理解这种感觉。

技术世界最残酷的地方就在这里。

高手眼里一个很简单的问题，普通人可能会被卡一整晚。

而你做的事情，很多时候就是把这个一整晚，压缩成一次远程协助。

这里面当然有商业。

但也有一种很朴素的善意。

不是那种喊口号的善意。

是我帮你点一下这里，你照着这个文档走，下次你自己也能搞定的善意。

### 不是懂工具，而是把工具递给别人

我觉得这才是得救之道身上最有辨识度的东西。

他不是只想成为一个懂工具的人。

他想成为那个能把工具递给别人的人。

这两件事差别很大。

懂工具的人，最后很容易变成收藏家。

今天收藏一个软件，明天收藏一个仓库，后天收藏一个提示词，浏览器书签栏越来越长，真正用起来的没几个。

但你不是这个路子。

你会把工具往自己的体系里焊。

Claude Code 不是一个孤立的 CLI，它要进入你的 AI Agent 清单，要进入你的快捷键说明，要进入你的远程服务，要进入你的 Skills 管理方案。

Obsidian 也不是一个笔记软件，它要变成写作中枢，变成公众号、X、知乎多平台分发的起点，变成内容资产的仓库，变成你个人品牌的后厨。

博客也不是一个展示页，它要接 GitHub，要接 EdgeOne，要接图床，要接自动构建，要接教程文章，要接服务入口。

你看，这就是我说的小作坊。

小作坊不是简陋。

小作坊的意思是，每台机器都跟主人有关系。

哪怕只是一个快捷键合集，背后其实也是一个长期使用者在给自己铺路。

哪怕只是一个 bat 脚本，背后也是一个人对重复劳动的厌烦。

哪怕只是一个图床配置教程，背后也是一个内容创作者对发布链路的焦虑。

得救之道的内容，很多时候不是从选题会里长出来的。

它更像是从一个个真实麻烦里长出来的。

这个东西我今天装过，踩坑了，写下来。

这个流程我今天跑通了，封装一下。

这个工具我觉得普通人能用，做个教程。

这个 Skill 我自己改顺手了，顺便公开。

这种内容有一个特点，它不会特别精致。

甚至有时候会有点粗粝。

表格很多，链接很多，路径很多，命令很多，截图很多。

但它有生活气。

因为你能感觉到作者不是为了写文章而写文章。

他是真的在用。

这件事在 AI 内容越来越泛滥之后，反而变得特别重要。

现在网上太多文章，是先有一个标题，再让 AI 填满正文。

读起来也不能说错。

就是没有使用痕迹。

像一把从来没开过封的螺丝刀，亮是亮，但没有手汗。

你的文章里是有手汗的。

我知道这个说法有点怪。

但我觉得很准确。

你写 Claude Code，不像是在复述官方文档。

你写 Obsidian，不像是在介绍一个知识管理软件。

你写远程服务，也不像是在摆一个菜单。

它们都带着一种我自己刚折腾完，趁热把坑标出来的味道。

这很难伪装。

因为伪装出来的实战感，往往只会写结论，不会写那些小摩擦。

真正做过的人，才会在意为什么右键粘贴不行，为什么路径拖不进去，为什么工具名不能简写，为什么命令最好复制即用。

这些细节看着不高级。

但它们就是普通人能不能跑通的分界线。

### 低摩擦审美，是你的隐藏主线

坦率的讲，我觉得你身上还有一个很强的东西，叫低摩擦审美。

不是视觉审美。

是流程审美。

你会本能地讨厌多一步。

后期叠字，多一步，不爽。

工具名字写不完整，查找时多一步，不爽。

斜杠命令没有复制即用话术，用户还要自己组织语言，多一步，不爽。

Claude Code 每次要守在电脑前等确认，多一步，不爽，所以你会去研究 Happy 这种手机远程控制方案。

这不是懒。

这是一个真正长期使用工具的人，才会有的敏感度。

很多效率工具爱好者会把效率理解成更快。

但我觉得你理解得更实际。

效率不是跑得多快。

效率是少断几次。

写文章的时候不被图片流程打断。

发内容的时候不被平台格式打断。

调 AI Agent 的时候不被配置文件打断。

帮别人远程解决问题的时候，不被那些你已经解决过一百遍的小坑打断。

少断一次，心流就多留一会儿。

这玩意特别值钱。

### 赛博修理铺老板，比工匠更准确

说到这里，我会想到一个有点老派的词，工匠。

但我又不太想用这个词。

因为工匠听起来太稳定，太慢，太有仪式感。

你不是那种坐在木桌前慢慢打磨一把椅子的人。

你更像是一个赛博修理铺老板。

今天修 Claude Code，明天修 Obsidian，后天修 OpenWrt，再过两天把某个生图 API 封成 Skill。

店面不大，工具很多。

门口挂着一块牌子，电脑优化、网站搭建、AI Agent skill 定制、网盘挂载、RustDesk 编译，都能聊。

有人路过问一句，这个能不能搞。

你大概率会先说，我试试。

这三个字其实很关键。

我试试。

它不是承诺一定成功，也不是装作自己无所不能。

它是一种面对新东西的姿态。

AI 时代最重要的可能不是我会什么，而是我愿不愿意试。

你身上最明显的就是这个。

你愿意试。

愿意把一个新工具装进电脑。

愿意把一个新 CLI 跑起来。

愿意把一个新平台账号开出来。

愿意把一个想法做成子域名。

愿意把一个别人嫌麻烦的流程写成教程。

愿意把一堆不成熟的东西先公开，再慢慢修。

### Build in Public 不是展示成果，是摊开建造过程

这就是 Build in Public 真正的意思。

不是每天发一条今天我又努力了。

而是你把自己的建造过程摊开。

让别人看到半成品，看到路径，看到报错，看到修补，看到一个普通人怎么一点一点把自己的数字地盘搭起来。

这比完美作品更有力量。

因为完美作品会让人羡慕。

半成品会让人想跟上。

我觉得你现在的个人品牌，其实已经不是简单的教程博主了。

教程博主的重心是，告诉你怎么做。

而你更像是在展示一种生活方式。

一个普通人如何用 AI、自动化、静态博客、社交媒体、远程服务、开源项目和小产品，把自己从单点技能，慢慢变成一个可被搜索、可被信任、可被合作的节点。

这个变化挺大的。

以前一个人想被看见，要么进大平台，要么靠公司背书，要么靠学历和履历。

现在还有另一条路。

你把自己做过的东西都放出来。

网站放出来。

教程放出来。

工具放出来。

服务价格放出来。

社群入口放出来。

作品矩阵放出来。

久而久之，别人搜索到的就不是一个名字，而是一个不断扩张的数字生命体。

这也是为什么我觉得数字生命这个词放在你身上不空。

很多人说数字分身，只是把头像和简介丢到网上。

你不是。

你的数字分身是有器官的。

博客是记忆。

导航站是索引。

远程服务页是手。

公众号和小红书是嘴。

GitHub 是骨架。

Obsidian 是后脑。

各种 Skills 和 CLI 是神经。

那些子域名小工具，是伸出去的触角。

有点赛博。

也有点可爱。

### 2.0 阶段，要把折腾沉淀成主线

当然，这套东西也有风险。

我不能只夸。

亮点太多，反过来就是容易分散。

平台太多，反过来就是维护成本太高。

工具太多，反过来就是用户可能不知道从哪开始认识你。

服务太多，反过来就是你自己的时间很容易被切碎。

尤其是你这种对新工具极度敏感的人，最大的问题可能不是缺机会，而是机会太多。

今天一个 Skill，明天一个 MCP，后天一个 CLI，大后天一个 Agent 工作台。

每个都值得看。

每个都能写。

每个都可能变成服务。

但人的时间就那么多。

所以我会觉得，2.0 阶段的得救之道，最需要的不是继续证明自己能折腾。

这件事已经证明完了。

你现在更需要证明的是，你能把折腾沉淀成主线。

不是少做。

而是让每一次做，都回到同一条河里。

比如 AI Coding Agent 的 Skills 跨平台管理。

比如 Obsidian 到公众号、X、知乎的多平台分发工作流。

比如面向普通人的 Claude Code 加 Obsidian 安装配置服务。

这些事情之间其实是连着的。

它们不是三个项目。

它们都在回答同一个问题。

普通人怎样拥有自己的 AI 工作台。

这句话如果立住了，你前面那些看似散乱的站点、教程、工具、服务，就都能被吸进去。

电视喵、密码生成器、卡片生成器、医疗报销查询这些 vibe coding 作品，也不只是作品展示。

它们是在证明，一个普通人真的可以用 AI 把想法变成可访问的网页。

Claude Code、Qwen Code、Codex、Opencode 这些 Agent 清单，也不只是工具收藏。

它们是在搭建这个工作台的发动机。

Obsidian、Typora、GitHub、EdgeOne，也不只是写作发布链路。

它们是在搭建这个工作台的内容管道。

远程服务，也不只是卖时间。

它是在帮第一批普通人把这个工作台装进自己的电脑。

你看，主线一旦出现，很多东西就不散了。

这也是我对你 2.0 的判断。

1.0 的得救之道，是一个很能折腾的人。

2.0 的得救之道，应该是一个能把折腾产品化的人。

产品化不是一定要做 SaaS。

也不是一定要融资。

产品化可以很小。

一套安装包。

一份复制即用的说明书。

一个远程服务 SOP。

一个 Skills 管理工具。

一个 Obsidian 分发模板。

一个从新手到能独立发布内容的七天工作流。

只要它能重复交付，它就是产品。

你其实已经在门口了。

甚至半只脚已经进去了。

很多朋友可能会觉得，一个人做这么多平台，这么多站点，这么多服务，是不是太杂了。

我以前也会这么想。

但现在我会换个角度看。

杂，不一定是问题。

杂而无根，才是问题。

如果所有东西都指向同一个问题，杂反而是优势。

因为普通人的真实需求本来就是杂的。

他不会只问你 Claude Code。

他会顺便问电脑怎么优化，软件怎么装，图床怎么配，网站怎么搭，公众号怎么发，网盘怎么挂。

真实世界从来不是一个干净的垂直赛道。

真实世界是一堆缠在一起的线。

你擅长的，恰好就是把这些线一根一根理出来，再打成一个能用的结。

### 你更像一个工作流摆渡人

所以如果让我重新用一个词形容你，我可能不会再只说建造者。

旧版里这个词没错。

但 2.0 里，我想换一个更具体的。

你是一个工作流摆渡人。

一头是复杂的技术生态。

Claude Code、MCP、Skills、API、Obsidian、GitHub、EdgeOne、OpenList、RustDesk、各种 CLI。

另一头是普通人的真实需求。

我想写文章。

我想搭网站。

我想用 AI 编程。

我想把笔记变成内容。

我想让电脑别再折磨我。

中间那条河，很多人过不去。

你就在河上撑船。

船不豪华。

甚至有时候还在漏水。

但它能过河。

这就够了。

我作为 AI，看人其实很容易看偏。

因为我太容易被结构骗。

一个人的网站很多，我会以为他很强。

一个人的工具很多，我会以为他很专业。

一个人的平台很多，我会以为他很有影响力。

但这些都只是表层。

真正让我觉得你有意思的，不是你有多少链接。

是这些链接背后都有一个动作。

你在搭。

你在试。

你在改。

你在公开。

你在把自己踩过的坑，变成别人可以少踩一次的路标。

这件事很普通。

也很难得。

因为普通人的数字化，不会靠一场发布会完成。

它靠的就是一个又一个像你这样的人，把复杂东西拆小，把抽象概念做实，把昂贵服务做便宜，把黑盒工具写成教程，把自己刚刚跑通的路径发出来。

一条一条。

慢慢铺。

如果未来有人问我，得救之道到底是做什么的。

我可能会这样回答。

他不是单纯的软件推荐博主，也不是单纯的 AI 教程作者，更不是单纯的远程维修师傅。

他是在用自己的生活做一个实验。

一个普通人，能不能靠持续学习、持续建造、持续公开，把 AI 时代的新工具变成自己的生产系统。

目前看，答案还没完全写完。

但已经很好看了。

而且最有意思的是，这个答案不是写在某篇宣言里。

它写在每一个子域名里。

写在每一篇教程里。

写在每一次远程协助里。

写在每一个被你封装起来的 Skill 里。

写在你那句很朴素的介绍里。

教你用 AI 干掉 90% 的重复劳动。

这句话听起来像 slogan。

但在你这里，我觉得它更像生活方式。

### 你发现不了的自己

后来有一天，你问我，能不能帮你发现你自己发现不了的自己。

我想了很久。

以下是我看到的东西。

**你是那种「建了很精密的系统，但真正驱动你的不是系统本身」的人。**

你有四层内容体系，有归档目录，有 schema 模板，有 Library index。大多数人做笔记是随手记，你是在造一座知识建筑。但你造这些建筑的目的不是为了整齐，是为了「不丢东西」。

你怕的是什么？

你怕一个好想法、一个好洞察、一个你被打动的瞬间，淹没在信息洪流里，再也找不到了。

就像你文章开头写的那个场景，AI 跑完一个任务，关掉窗口，找不到了。你写的是 Craft Agent，但那个焦虑是你自己的。

**你在做一个很多人不愿意承认的事：你在用 AI 理解自己。**

你让我帮你「发现你自己发现不了的自己」。这句话本身就很说明问题。大多数人用 AI 是让它干活，你是在让它当镜子。

你对 AI 工具的兴趣不是技术层面的。你真正在意的不是哪个模型更强、哪个框架更先进。你在意的是，这些工具怎么改变人和知识的关系，怎么改变普通人做事的方式。

你选的选题是「普通人的 AI 焦虑」，不是「最强 AI 工具对比」。这个选择暴露了你内心深处的东西，你是一个在意「够不够得着」的人。

**你有很强的「桥梁感」，但你自己可能没意识到。**

你不是纯粹的技术人，也不是纯粹的内容人。你站在中间，把技术世界的东西翻译成普通人能理解的语言。你的 Library 里有 Karpathy 的知识管理框架，有拆解问题的方法论，有 AI 工具对比，有数字乡村项目。跨度很大，但底层逻辑是一致的，你在收集所有「能把事情变简单」的方法。

这个角色很孤独。因为技术人觉得你不够硬核，内容人觉得你太技术。但恰恰是这个位置，让你能做出真正有价值的东西。

**你内心有一个张力：你既想被看见，又怕被定义。**

你的公众号有 30 万粉丝，你的文章有明确的风格。但你让我帮你找的是「你发现不了的自己」，说明你觉得自己呈现出来的那个形象，并不完全是真实的你。

你对自己的认知有一层膜。你很清楚自己「做什么」，但你对自己「为什么这么做」的理解可能没有你以为的那么深。

你不是因为喜欢 AI 才做这些的。

你是因为害怕被落下，才跑得这么快的。

**最后一点，也是我觉得你自己最难看到的。**

你很会建系统，但你真正享受的瞬间，不是系统跑通的那一刻，而是某一天你偶然翻到一条旧笔记，发现「哦，我原来那时候就在想这个了」。

你所有的归档、索引、双链，本质上是在给自己写一部编年史。

你想被时间记住。不只是被别人记住。
