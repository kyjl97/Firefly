# 未来选题调整计划

## 一、调整目标

过去的博客已经积累了大量 AI 工具、Codex、Claude Code、Obsidian、软件教程和自动化内容。后续不需要继续扩大范围，重点是把内容收拢到真实需求和已经验证的服务上。

未来选题要完成三件事：

1. 让遇到安装、配置和报错问题的人能够搜到我
2. 让读者通过真实案例了解我怎样判断和解决问题
3. 让低门槛需求逐步进入工作流搭建、Skill 定制和个人网站服务

核心路径：

```text
具体报错或使用障碍
→ 教程、案例和检查清单
→ 软件安装与远程排错
→ Codex / Claude Code + Obsidian 工作流
→ Skill、自动化和个人网站定制
```

## 二、未来内容方向比例

### 按业务方向分配

- 40%：AI 工具安装、Windows 环境配置与报错修复
- 30%：Codex、Claude Code 与 AI Agent 实际使用
- 20%：Obsidian 知识管理、写作与 AI 工作流
- 10%：个人网站、内容发布流程及与服务直接相关的热点

### 按内容形式分配

- 60% 具体问题：安装失败、配置不会、API 接入、软件报错和使用障碍
- 30% 真实案例：记录问题环境、判断过程、解决办法和最终结果
- 10% 工具变化：只讲与普通用户、现有工作流和付费服务直接相关的新变化

## 三、选题优先级

### P0：直接付费需求

用户已经遇到问题，并且可能愿意付费解决。

重点词：安装失败、打不开、启动崩溃、配置不会、API 报错、登录异常、远程修复、环境检查。

### P1：建立信任与升级服务

用户暂时不急着付费，但正在寻找一套更完整的使用方法。

重点词：实际使用、完整流程、工作台、知识库、自动化、前后对比、真实案例。

### P2：工具变化与热点

只有能连接 P0 或 P1 时才做。纯融资、模型跑分、宏大行业讨论和无法核实的一手消息不优先。

每个选题发布前检查：

- 是否对应一个具体的人和具体问题
- 是否来自自己用过、装过、修过或真实测试过的内容
- 是否能够给出步骤、判断方法或实际结果
- 是否可以自然对应一项服务
- 是否与近30天已经发布的文章重复

## 四、方向一：AI 工具安装与远程排错

**核心角度**：用真实 Windows 环境、报错截图和排查过程，解决用户最急的问题。

**对应服务**：软件安装、环境配置、远程排错、技术咨询。

**工作量评估**：⭐⭐，需要复现步骤或保留真实服务记录。

### 示例标题

1. Windows 安装 Codex App，一打开就崩溃，我最后查到了 Astrill
2. 为什么你照着教程安装 Claude Code，还是一直报错？
3. 安装 AI 编程工具前，先检查电脑里的这5项环境
4. Codex App 安装成功却打不开，应该从哪一层开始排查？
5. Claude Code 输入命令没有反应，可能卡在这4个地方
6. Node.js、Git 和环境变量，哪个最容易让 AI 工具安装失败？
7. 用户只说“软件不能用”，我是怎样一步步定位问题的
8. 远程安装 AI 工具时，我最先检查的5个地方
9. AI 软件安装完成后，怎样才算真正交付成功？
10. 一个报错值不值得远程处理？先用这张检查清单判断

### 优势

- 已有真实成交，离付费需求最近
- 搜索意图明确，文章生命周期较长
- 问题解决后可以沉淀 SOP、检查清单和远程服务案例

### 风险

- 工具版本更新后，教程需要复查
- 不能只堆安装命令，必须说明适用环境和验证结果

## 五、方向二：Codex、Claude Code 与 AI Agent

**核心角度**：帮助普通用户从“安装成功”走到“真正进入日常工作”。

**对应服务**：Codex App 指南、Agent 安装配置、AI 工作台搭建、Skill 定制。

**工作量评估**：⭐⭐⭐，多数选题需要真实运行、截图和完整案例。

### 示例标题

1. 我把 Codex 用成 AI 工作台后，每天少做了哪些重复操作？
2. Codex App 安装以后，普通用户应该先学哪5个功能？
3. Codex、Claude Code 和普通聊天 AI，到底有什么区别？
4. 第一次使用 Codex，工作目录应该怎么选？
5. Codex 为什么读不到你的文件？先检查权限和工作目录
6. 我怎样让多个 AI Agent 共用一套 Skills？
7. Agent 装得越来越多，怎样避免每个工具都重复配置？
8. 一个重复工作，什么时候值得封装成 AI Agent Skill？
9. 我用 Codex 整理博客文章时，哪些规则必须提前写清楚？
10. Codex App 指南卖出几单后，我发现新手真正卡住的是这些地方

### 优势

- 已有 Codex App 指南成交，可以继续验证需求
- 能连接安装服务、知识库、自动化和 Skill 定制
- 容易形成系列教程和付费知识产品

### 风险

- 不要把每个新 Agent 都单独写成一篇泛介绍
- 功能介绍必须落到一个真实任务，避免变成工具清单

## 六、方向三：Obsidian 与个人工作流

**核心角度**：减少单独销售模板，重点展示一套工作流怎样解决选题、素材、写作、发布和知识管理问题。

**对应服务**：Obsidian 配置、知识库搭建、写作工作流、模板配置、Codex 与 Obsidian 集成。

**工作量评估**：⭐⭐⭐，需要展示真实使用过程和前后变化。

### 示例标题

1. 我的 Obsidian 模板为什么没有卖出去？
2. 下载了很多 Obsidian 模板，为什么最后一套都没用起来？
3. 个人创作者的 Obsidian，到底需要几个文件夹？
4. 我怎样用 Obsidian 管理选题、素材、文章和发布记录？
5. Obsidian 模板导入以后，第一步应该删掉什么？
6. 我把 Codex 接入 Obsidian 后，哪些整理工作不用手动做了？
7. Obsidian + Git 自动备份，新手最容易卡在哪一步？
8. 怎样把微信、网页和其他平台的内容统一收进 Obsidian？
9. 什么人适合买 Obsidian 模板，什么人更适合定制工作流？
10. 从一条灵感到一篇文章，我的 Obsidian 写作流程是怎样跑起来的？

### 优势

- 与现有文章和个人使用经验高度一致
- 可以把模板变成免费体验、数字产品或工作流交付组件
- 容易升级到 Codex + Obsidian 个人 AI 工作台

### 风险

- 模板目前没有出单，不能继续只展示页面和插件功能
- 案例要强调用户结果，不能默认所有人都需要复杂知识库

## 七、方向四：个人网站与内容发布工作流

**核心角度**：帮助个人创作者把内容资产变成可以长期访问、搜索和展示的网站。

**对应服务**：个人主页、简历网站、笔记网站、博客部署和内容发布工作流。

**工作量评估**：⭐⭐，教程需要截图、部署记录和可访问案例。

### 示例标题

1. 普通人搭个人网站，真正需要准备哪些东西？
2. 我没有服务器，博客是怎样自动发布的？
3. Obsidian 笔记怎样同步成一个可以访问的网站？
4. 个人主页、简历网站和博客，应该先搭哪一个？
5. GitHub + EdgeOne 部署博客，最容易出错的5个地方
6. 本地预览正常，网站上线后为什么图片全没了？
7. 我怎样把写文章、上传图片和发布网站做成一套流程？
8. 给创作者搭网站时，我会先问清楚哪6个问题？
9. 个人网站搭好以后，怎样避免长期没人更新？
10. 网站搭建完成后，客户应该拿到哪些账号、文件和说明？

### 优势

- 有自己的博客、主页、简历和工具网站作为真实案例
- 交付结果直观，适合展示前后对比
- 可以与 Obsidian、Git 和内容发布工作流连接

### 风险

- 当前没有明确的成交数据，先用内容和咨询量验证需求
- 不要只讲建站技术，要说明网站为谁服务、解决什么问题

## 八、热点内容的使用规则

热点不单独成为主线，只作为以上四个方向的补充。

可以做：

- Codex、Claude Code 或 Obsidian 更新后，安装和工作流发生了什么变化
- 新的 AI Agent 是否值得普通用户安装
- 某项功能更新解决了哪个具体问题
- 官方规则变化对现有用户有什么影响

减少做：

- 与现有服务没有关系的融资和收购新闻
- 没有官方来源的重大消息
- 只复述发布会和产品功能
- 无法给普通用户行动建议的行业观点

## 十、单篇文章写作模板

每篇文章尽量按照这个顺序：

1. 具体问题：用户在什么环境下遇到了什么问题
2. 初步判断：最可能是哪几层原因
3. 实际过程：检查、尝试、失败和修复步骤
4. 最终结果：解决到什么程度，怎样验证
5. 适用边界：哪些情况可以照做，哪些情况需要另外处理
6. 服务承接：没有时间继续排查的人，可以选择对应的安装、排错或搭建服务

不要把“加微信、购买、评论区打关键词”塞进每篇文章。优先让读者看到真实解决能力，再在文末保留一个与本篇问题直接相关的服务入口。

## 十一、每月复盘指标

每月底记录：

- 每个方向发布了多少篇
- 哪些文章获得搜索访问、收藏和转发
- 哪些文章带来了咨询
- 咨询者具体卡在什么问题
- 哪类服务最终成交
- 每项服务用了多少交付和售后时间
- 哪些问题重复出现，可以做成教程、SOP、脚本或 Skill

如果一个方向连续发布5篇仍然没有搜索、咨询或真实互动，先检查标题和分发，再决定是否降低比例。不要只凭一篇文章的数据判断整个方向没有需求。
