# 选题参考指南

这份文档用于以后没选题、选题发散、或者需要让 AI 帮我判断选题时作为参考。

我的内容不是单纯写技术博客，也不是泛泛追 AI 新闻，而是围绕一个核心定位展开：

> 面向普通人的 AI 工作流和数字生产力实践，专注把 AI Agent、Obsidian、效率工具、内容创作流程，变成可落地的教程、方法和服务。

一句话人设：

> 得救之道，一个数字生产力玩家、Build in Public 践行者、工作流构建者，专注帮普通人用 AI 和自动化工具干掉重复劳动。

---

## 一、我的核心写作方向

### 1. AI Agent / AI Coding / Skill 生态

这是当前最重要的主线。

适合写：

- Claude Code、Codex、Gemini CLI、Qwen Code、OpenCode 等 AI 编程工具
- MCP、Skill、Sub Agent、CLI 工具链、AI Agent 工作台
- 国产模型接入、API 中转、OpenRouter、模型切换、免费额度
- AI Coding 的真实体验、踩坑、配置、提效方法
- 把一个重复流程封装成 Skill / Agent / 自动化工具

选题判断：

- 是否能解决一个真实配置问题？
- 是否能让普通人照着做出来？
- 是否能沉淀成我的个人工作流或服务能力？
- 是否能解释 AI Agent 时代的工作方式变化？

典型标题方向：

- 《Claude Code 装完不会用？我整理了一套新手工作流》
- 《AI Skill 的价值，不是聊天，而是把经验封装成工具》
- 《普通人怎么开始用 AI Coding？先从这 3 类任务练手》

### 2. Obsidian / 知识管理 / 内容工作流

这是第二条稳定主线。

适合写：

- Obsidian 插件、同步、模板、Dataview、Templater
- 微信读书、网页剪藏、公众号素材、链接收藏进入 Obsidian
- Obsidian 到博客、公众号、X、知乎、小红书的分发流程
- LLM Wiki、Karpathy 知识库方法、AI 知识库实践
- 把笔记变成 Skill、文章、选题库、素材库

选题判断：

- 是否降低了记录、整理、写作、发布的摩擦？
- 是否能把“收藏资料”变成“可调用能力”？
- 是否能把 Obsidian 和 AI Agent 连接起来？

典型标题方向：

- 《把 Obsidian 笔记变成博客，我终于不用登录后台了》
- 《读书笔记的下一步，不是整理得更漂亮，而是变成 Skill》
- 《我的 Obsidian 内容生产工作流：从收藏到发布》

### 3. 软件安利与效率工具教程

这是最容易持续产出的基础内容线。

适合写：

- 截图、录屏、终端、启动器、剪藏、图床、同步、压缩、远程控制工具
- Windows 效率工具、开源小工具、Chrome 插件
- 工具之间的组合方案，而不是单个工具介绍
- 个人真实使用后的配置、避坑、替代方案

选题判断：

- 这个工具是否解决高频痛点？
- 是否比同类工具更省事？
- 是否有“普通人一看就想装”的价值点？
- 是否能接入我的 AI / 写作 / 工作流体系？

典型标题方向：

- 《这款截图工具我用了一段时间，真正好用的是快捷动作》
- 《几个推特/X 辅助插件，适合内容创作者蹲热点》
- 《Windows 右键菜单太乱？这个工具能一口气清理干净》

### 4. 博客、图床、部署、个人网站搭建

这是强化个人品牌和服务转化的内容线。

适合写：

- Fuwari、VitePress、Cloudflare Pages、EdgeOne、GitHub Pages
- 图床搭建、封面图、画廊、博客发布脚本、自动部署
- 个人主页、导航站、简历站、数字工坊
- 建站过程中的 bug、修复记录、配置经验

选题判断：

- 是否能帮助别人搭建自己的展示系统？
- 是否能体现我的 Build in Public？
- 是否能带出远程服务、模板、脚本、项目仓库？

典型标题方向：

- 《我用 GitHub + EdgeOne 搭了一个无服务器博客》
- 《零成本搭建在线图床，写文章终于不用手动传图了》
- 《记录一次博客导航栏抖动修复：问题居然不在动画》

### 5. 普通人 AI 破局 / AI 时代个人生产力

这是观点类内容线，适合扩大传播。

适合写：

- 普通人如何使用 AI 提升收入、效率、表达、创作能力
- AI 副业、兴趣变现、内容创作、自动化服务
- AI 时代个人能力结构变化
- 不鼓吹暴富，强调真实路径、低成本验证、长期积累

选题判断：

- 普通人能不能看懂？
- 是否有现实焦虑或真实痛点？
- 是否能给出可执行的一步，而不是空喊趋势？
- 是否能结合我自己的经历和案例？

典型标题方向：

- 《普通人的 AI 破局之路：先别想着赚钱，先开始产出》
- 《用 AI 两年，我劝你别太依赖它》
- 《AI 不是副业答案，但它能把你的产出效率放大》

### 6. 轻技术实操服务类内容

这是和商业服务最贴近的内容线。

适合写：

- Win 系统重装、电脑优化、软件安装、报错修复
- OpenList / Alist 网盘挂载、RustDesk、远程控制
- PassWall、软路由、云主机、网站加速、DNS 配置
- API 泄露、GitHub 推送、环境变量、基础安全

选题判断：

- 是否有人愿意为这个问题付费找人解决？
- 是否能做成远程服务 SOP？
- 是否能沉淀成教程、脚本、工具包？

典型标题方向：

- 《我 push 博客时泄露了 API，完整复盘一次》
- 《OpenList 挂载网盘，从 0 到 1 配置记录》
- 《三步搞定软件汉化，适合新手照着做》

## 二、我的目标读者画像

我的核心读者不是纯程序员，也不是完全小白，而是：

> 有折腾意愿的普通人、内容创作者、效率工具爱好者、AI 工具玩家、轻技术副业人群。

### 1. AI 工具尝鲜者

他们关注 Claude Code、Codex、Gemini CLI、MCP、AI Agent，但不一定有系统开发能力。

他们需要：

- 安装教程
- 配置方案
- API 接入
- 避坑经验
- 可复制工作流

### 2. 内容创作者 / 自媒体人

他们关心选题、写作、封面、配图、多平台分发、公众号/X/即刻/小红书同步。

他们需要：

- 更快写文章
- 更快做封面
- 更快生成社交媒体版本
- 把热点变成内容
- 把内容发布到多个平台

### 3. Obsidian 和知识管理用户

他们已经在记笔记，但想把笔记变成博客、知识库、Skill、内容资产。

他们需要：

- 插件教程
- 模板方案
- 同步方案
- 笔记发布方案
- 知识库变现或产品化思路

### 4. Windows 效率工具用户

他们喜欢装软件、调快捷键、优化系统、折腾截图、录屏、终端、自动化脚本。

他们需要：

- 好工具推荐
- 配置步骤
- 同类工具对比
- 真实使用场景
- 少踩坑

### 5. 想靠 AI 提升收入或能力的普通人

他们不是开发者，但想知道 AI 能不能帮自己做副业、做工具、做内容、做自动化。

他们需要：

- 看得懂的解释
- 真实案例
- 低成本开始方法
- 不夸张的路径
- 可以今天就试的一步

## 三、选题优先级

以后选题时，优先级按这个顺序判断：

### S 级：最值得写

满足其中 3 条以上：

- 和 AI Agent / Skill / Obsidian / 工作流强相关
- 我自己真实用过、改造过、踩坑过
- 普通人照着能复现
- 可以沉淀成服务、工具、模板或脚本
- 能体现“AI 干掉重复劳动”
- 能连接内容创作、知识管理或自动化

### A 级：可以写

满足其中 2 条：

- 工具确实好用
- 有明确使用场景
- 有教程价值
- 能帮读者省时间
- 能形成经验清单或避坑指南

### B 级：谨慎写

只有新闻热度，但没有我的实践、观点或工作流连接。

比如：

- 单纯某模型发布
- 单纯某公司融资
- 单纯榜单、名单、参数对比
- 只有转述，没有我的使用体验

除非能转成：

- 普通人怎么用
- 对内容创作者有什么影响
- 对 AI Agent 工作流有什么启发
- 我能不能拿来做一个工具或流程

## 四、我适合写的文章类型

### 1. 手把手教程

适合工具安装、配置、部署类内容。

结构：

1. 痛点开场
2. 这个工具解决什么问题
3. 准备工作
4. 安装步骤
5. 核心配置
6. 常见问题
7. 我的使用建议

### 2. 工作流拆解

适合 Obsidian、AI 写作、内容发布、Agent 自动化。

结构：

1. 我以前怎么做
2. 问题卡在哪里
3. 现在的新流程
4. 每一步用什么工具
5. 成本和收益
6. 谁适合，谁不适合

### 3. 工具测评 / 安利

适合软件、插件、AI 工具。

结构：

1. 一句话说清楚它干什么
2. 最打动我的 3 个功能
3. 使用场景
4. 配置建议
5. 同类工具对比
6. 下载地址 / 项目地址

### 4. 观点文 / 趋势文

适合 AI 时代、普通人破局、AI Coding、知识管理变化。

结构：

1. 一个真实故事或热点开场
2. 提出核心判断
3. 拆 2-4 个原因
4. 结合自己的经历
5. 给普通人的行动建议
6. 收束到一句可传播观点

### 5. 踩坑复盘

适合 bug、报错、部署失败、安全问题、工具翻车。

结构：

1. 发生了什么
2. 我一开始怎么判断
3. 真正原因是什么
4. 怎么解决
5. 以后怎么避免
6. 给读者的检查清单

## 五、标题方向参考

### 教程类标题

- 《XXX 安装与配置完整教程》
- 《新手也能跟着做：XXX 从 0 到 1》
- 《我把 XXX 接入了 Claude Code，过程记录一下》
- 《XXX 配置踩坑记录：这几个地方最容易出错》

### 工作流类标题

- 《我的 XXX 工作流：从输入到发布》
- 《我用 AI 把 XXX 流程自动化了》
- 《从 Obsidian 到公众号，我搭了一套自动发布流程》
- 《一句话触发，AI 自动帮我完成 XXX》

### 观点类标题

- 《XXX 的价值，不是 XXX，而是 XXX》
- 《普通人真正该学的，不是工具，而是工作流》
- 《AI 时代，最容易被低估的是 XXX》
- 《别再只把 AI 当聊天工具了》

### 工具安利类标题

## 六、不适合我的选题

尽量少写：

- 纯 AI 新闻搬运，没有观点和实践
- 纯参数对比，没有使用场景
- 过度宏大的科技伦理、国际关系、资本市场分析
- 和我工作流无关的泛科技资讯
- 只适合专业程序员的深度源码分析
- 没有复现、没有截图、没有步骤的空泛推荐

如果一定要写，必须转成我的角度：

- 这个新闻对普通人有什么用？
- 这个工具能不能进入我的工作流？
- 这个变化会不会影响内容创作者？
- 它能不能变成教程、服务、脚本、Skill？

## 七、给 AI 的选题提示词

以后没有选题时，可以把这段发给 AI：

```text
请根据我的选题参考指南D:\project2026\fuwari\src\content\Xenia\选题参考指南.md
结合今天的 AI 热点 / 工具动态 / 我近期关注的内容，帮我筛选 5 个适合我写的文章选题。

要求：
1. 优先选择 AI Agent、Skill、Obsidian、内容工作流、效率工具、普通人 AI 应用相关方向。
2. 不要只给新闻标题，要转成我的写作角度。
3. 每个选题请输出：
   - 推荐标题
   - 适合我的原因
   - 目标读者
   - 文章切入点
   - 可写大纲
   - 是否适合做教程 / 观点文 / 工作流拆解 / 工具安利
4. 优先推荐能落地、能复现、能连接我的服务或工作流的选题。
5. 避免空泛趋势文和纯新闻搬运。
```

如果已经有候选热点，可以用这段：

```text
下面是今天的候选热点，请按我的选题参考指南判断哪些值得写。

请你分成三类：
1. 最值得写：能形成文章、教程或工作流。
2. 可以蹭：适合做短内容或社交媒体动态。
3. 不建议写：和我的定位弱相关，或者只有新闻价值。

每个推荐项请说明：
- 为什么适合我
- 可以写给谁看
- 最好的切入角度
- 建议标题
- 是否需要进一步查资料或亲自测试
```

> 普通人如何用 AI Agent、Obsidian、效率工具和自动化工作流，把重复劳动变成系统，把个人经验变成可复用能力。

这条线可以连接：

- 教程
- 工具
- 工作流
- 观点
- 服务
- 社群
- 模板
- Skill
- 开源项目

不要只追热点，要把热点放进自己的系统里。
