刚在刷 B 站，发现了一个大佬开发的飞书搜索命令行工具，觉得挺有意思，分享给大家。

这个工具确实非常有价值。因为像我自己的飞书里有十几个知识库，有时候突然想找一份文档，得打开网页或本地客户端，点进对应知识库，搜关键词，再翻页找正文——这一套下来至少 50秒过去，思路早被打断了。有了这个工具，我只需要敲一个命令，结果就在终端里实时过滤，回车直接打开。

> **开源地址**：chriszou/larkdoc>

但是这篇文章真正要解决的，不是「这个工具怎么用」，而是「装上之后跑不起来怎么办」。我把它跑通踩了 6 个错、两次编译、一次 OAuth 授权——把这一路整理出来，能帮你少走一整天的弯路。

## 一、为什么你大概率会卡在第一步

立靶子：你以为「下载安装 → 跑命令」就能用？第一跑 `larkdoc sync --full` 大概率会报错。

这不是你的问题，是工具本身没跟上运行环境演化。具体来说，是三方栈之间出现了**契约漂移**。

第一层，工具假设 lark-cli 支持 `--json` flag，但当前 `@larksuite/cli` 已经移除。
第二层，工具假设 lark-cli 默认是 user 身份，但当前版本默认走 bot。
第三层，工具假设在普通终端运行，但 Codex 桌面会注入 Hermes 网关变量。
第四层，工具假设 user token 一直有效，但 OAuth token 过期后需要重新授权。

四层假设同时失效，你就会看到一条报错链：未知 flag → 身份不对 → Hermes 误识别 → 权限不足。一个接一个，每个都要单独处理。

**所以这篇文章的核心不是「安利工具」，而是「陪你走完这条报错链」。**

## 二、安装：先把程序装上

### Windows 用户

直接去 [Releases](https://github.com/ChrisZou/larkdoc/releases) 页面下载 `larkdoc_<版本>_windows_amd64_setup.exe`，运行安装包。

安装程序会自动把 larkdoc 加入当前用户的 `PATH`，无需手动配置。装完重开一个终端，敲 `larkdoc version`，看到版本号就说明装好了。

### macOS / Linux 用户

```bash
go install github.com/chriszou/larkdoc@latest
```

或者直接下载源码 `go build`。

## 三、使用：4 个核心命令

```bash
larkdoc                  # 交互式全文搜索（启动时后台自动增量同步）
larkdoc sync             # 增量同步元数据 + 正文到 ~/.larkdoc/
larkdoc sync --full      # 全量重建索引（清理已删除或取消共享的文档）
larkdoc list             # 以 TSV 打印索引：title / type / updated / url
larkdoc alfred [query]   # 输出 Alfred Script Filter JSON（供 Alfred workflow 调用）
```

日常最高频的两个：`larkdoc`（直接进搜索）和 `larkdoc sync`（后台同步）。

`larkdoc sync --full` 第一次会全量拉所有有权限的文档 + 正文，**会跑几分钟**。`larkdoc` 启动时会在后台自动做增量同步，状态栏显示进度，完成后热更新结果。

## 四、报错链第一段：源码适配

报错链通常是按这个顺序出现的：

### 4.1 `unknown flag: --json`

```
错误: lark-cli 调用失败: Error: unknown flag: --json
```

**根因**：larkdoc v0.1.1 在源码里给 `lark-cli` 调用加了 `--json` flag，但当前 lark-cli 早就移除了这个 flag。lark-cli 现在用 `--format` 控制输出格式，默认就是 JSON。

**解法**：从源码重新编译，删掉 `--json`。

### 4.2 `resolved identity "bot" not supported`

```
resolved identity "bot" (via auto-detect or default-as) is not supported,
this command only supports: user
```

**根因**：`lark-cli drive +search` 和 `docs +fetch` 只允许 user 身份。但 larkdoc 没传 `--as user`，lark-cli 默认走 bot 就直接报错。

**解法**：源码里所有调 `lark-cli` 的地方都加上 `--as user`。

### 4.3 `hermes context detected but lark-cli is not bound to it`

```
hermes context detected but lark-cli is not bound to it
```

**根因**：Codex 桌面启动外部命令时会注入一组 Hermes 网关环境变量。lark-cli 启动时探测这 5 个变量（`HERMES_HOME` / `HERMES_QUIET` / `HERMES_EXEC_ASK` / `HERMES_GATEWAY_TOKEN` / `HERMES_SESSION_KEY`），只要命中任意一个就判定自己是「被 Hermes 网关调用」，如果没有绑定过这个 Hermes 就拒绝执行。

**关键坑**：网上很多教程（包括我自己之前写的踩坑日志）告诉你「清掉 `HERMES_HOME` 和 `HERMES_GIT_BASH_PATH`」就够——**但 `HERMES_GIT_BASH_PATH` 不在 lark-cli 的检测列表里**，清它没用。真正要清的是上面那 5 个变量，而且 Hermes 网关通常会同时注入多个，只清一个大概率不够。

**解法**：源码层加一个 helper，过滤这 5 个变量后再调 lark-cli。

### 4.4 `need_user_authorization`

```
API call failed: need_user_authorization,
current command requires scope(s): search:docs:read
```

**根因**：源码层修对了，但飞书的 `drive +search` 接口需要 `search:docs:read` scope。larkdoc 调用时用的是 user 身份，如果后台没开通这个 scope 或者 user token 过期，就会报这个错。

**解法**：去飞书开放平台给应用开通 `search:docs:read` scope，然后重新做一次 OAuth 授权让 user token 带上新权限。

## 五、源码层修复：4 处改动 + 1 个 helper

不是要你去改然后提 PR，是让你看到这个工具到底要怎么补。改完照样编译照样用。

### 5.1 改 4 处源码

| 文件 | 行 | 改动 |
|------|-----|------|
| `sync.go` | 106 | 删除 `--json,` |
| `sync.go` | 103 | 新增 `--as user` |
| `content.go` | 156 | 删除 `, "--json"` + 新增 `--as user` |
| `content.go` | 8 | 删除不再使用的 `os/exec` import |

### 5.2 加一个 helper 文件 `larkcli.go`

```go
package main

import (
    "os"
    "os/exec"
    "strings"
)

// Hermes 网关注入的 5 个检测变量 + 1 个常见配套变量
// 来源：lark-cli 源码 internal/core/workspace.go:113-117
var hermesVars = []string{
    "HERMES_HOME", "HERMES_QUIET", "HERMES_EXEC_ASK",
    "HERMES_GATEWAY_TOKEN", "HERMES_SESSION_KEY", "HERMES_GIT_BASH_PATH",
}

func larkCLIEnv() []string {
    env := os.Environ()
    out := make([]string, 0, len(env))
    for _, kv := range env {
        skip := false
        for _, h := range hermesVars {
            if strings.HasPrefix(kv, h+"=") {
                skip = true
                break
            }
        }
        if !skip {
            out = append(out, kv)
        }
    }
    return out
}

func larkCLICommand(args ...string) *exec.Cmd {
    cmd := exec.Command("lark-cli", args...)
    cmd.Env = larkCLIEnv()
    return cmd
}
```

### 5.3 把 `sync.go` 和 `content.go` 里的 `exec.Command("lark-cli", ...)` 都换成 `larkCLICommand(...)`

### 5.4 编译 + 替换

```bash
go build -ldflags "-s -w" -o larkdoc_patched.exe .
cp larkdoc_patched.exe "C:\Users\Administrator\AppData\Local\Programs\larkdoc\larkdoc.exe"
```

**编译前先备份原 exe**——出问题能 `unins000.exe` 走卸载流程，或者直接把备份覆盖回去。

## 六、用户授权：源码修对了还会卡

源码层修完只是让工具能调到 lark-cli，但调 API 还需要 scope 和 token。两件事要做：

### 6.1 后台开 scope（最小权限）

登录飞书开放平台 → 找到应用（我的是 `cli_a945002535781cb0`）→ 权限管理 → 搜索 `search:docs:read` → 开通。

只开需要的这一个，不要顺手开一票。最小权限原则。

### 6.2 重新做 user OAuth 授权

后台开了 scope 不等于 token 拿到了。后台开 scope + 前端重新 OAuth 是两件事，必须都做。

**在 PowerShell 里**（注意先清 Hermes 变量，否则 lark-cli 自己跑不起来）：

```powershell
$hermesVars = @('HERMES_HOME','HERMES_QUIET','HERMES_EXEC_ASK','HERMES_GATEWAY_TOKEN','HERMES_SESSION_KEY','HERMES_GIT_BASH_PATH')
foreach ($v in $hermesVars) { Remove-Item "Env:$v" -ErrorAction SilentlyContinue }
lark-cli auth login
```

浏览器跳到飞书 OAuth 页面，确认授权。回来 user token 就刷新了，会自动带上你刚开的 `search:docs:read`。

### 6.3 验证

```powershell
lark-cli auth status
```

正常应该看到 `"identity": "user"`，而不是 `"identity": "bot"`。如果还是 bot，说明 token 没刷新成功，重新跑一次 auth login。

## 七、把它装进你的终端：3 套集成

源码修好、scope 开好、token 刷新好之后，最后一步是让它在你终端里随手可调。

### 7.1 PowerShell（Windows 默认终端）

编辑 `C:\Users\Administrator\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`，加一行：

```powershell
Set-Alias lk larkdoc
```

> **踩坑**：Windows PowerShell 5.x 不识别 UTF-8 无 BOM 文件里的中文注释，会让整个 profile 加载失败（连带 oh-my-posh、代理设置全部失效）。所以这行**不要加注释**。

### 7.2 nushell（WezTerm 默认 shell）

如果你用 WezTerm + nushell，编辑 `C:\Users\Administrator\AppData\Roaming\nushell\config.nu`：

```nu
# 敲 lk 直接进 TUI 搜索
alias lk = larkdoc

# 一键清掉 Hermes 网关注入的 6 个变量
def --env "hermes off" [] {
    load-env {
        HERMES_HOME: "",
        HERMES_QUIET: "",
        HERMES_EXEC_ASK: "",
        HERMES_GATEWAY_TOKEN: "",
        HERMES_SESSION_KEY: "",
        HERMES_GIT_BASH_PATH: ""
    }
    print "已清空 6 个 Hermes 环境变量"
}
```

以后跑 `larkdoc sync --full` 之类的命令前，敲一下 `hermes off` 就清干净了。

### 7.3 WezTerm 启动菜单

编辑 `~/.wezterm.lua` 的 `launch_menu`：

```lua
config.launch_menu = {
  { label = 'NuShell', args = { 'nu.exe' } },
  { label = 'PowerShell', args = { 'powershell.exe' } },
  { label = 'Cmd', args = { 'cmd.exe' } },
  { label = 'larkdoc 飞书文档搜索', args = { [[C:\Users\Administrator\AppData\Local\Programs\larkdoc\larkdoc.exe]] } },
}
```

> 用绝对路径，不要写 `larkdoc.exe`——系统 PATH 里没有这个目录。

## 九、这种工具值不值得这么折腾

值得，但有条件。

**判断标准**：第一，这个工具每天用几次？如果一天用不到一次，别折腾。第二，文档分散在多少个知识库？如果就一个，飞书自带的全局搜索够用。第三，你是不是已经会改 Go 源码？如果完全不会，这篇文章的源码部分就是黑盒。

**真正值得折腾的场景**：你像我一样，文档分散在 5 个以上知识库，每天要找文档 3 次以上，并且愿意把「遇到报错」当成「补一节系统设计课」。

这个工具的本体价值不大——它就是把飞书的搜索 API 包了一层 TUI。**它的真正价值是让你在这个过程中补齐三方栈契约的理解**：lark-cli 怎么调用、飞书 OAuth 怎么流转、Hermes 桌面环境怎么注入变量。这些经验下次写别的工具时还能复用。

工具从来不是装出来用的，是改出来用的。你愿意为它改源码、补 scope、调通三方协议，它就会回报你一个「想找文档就找文档」的工作流。你不愿意，那直接用飞书网页搜索也挺好。
