今天，我拥有了一支 **14 人的 AI 团队**。

它就住在我飞书的聊天框里。发一条消息，它写文章、查资料、核事实、审稿、排版，还能给我出短视频脚本。

更离谱的是：**这 14 个 AI 员工 24 小时待命，成本几乎为零**。

这篇记录一下我是怎么把它搭出来的——包括那些差点把我劝退的坑。

![](https://gitee.com/da-qiang-classmate/typora/raw/master/image/cover-ai-team-14-20260805-v2.webp)


### 01.事情起因

Vercel Labs 开源了一个叫 **eve** 的 Agent 框架，还配了个「营销团队模板」：

一个主管 AI，带 5 个专家 AI（品牌定位、文案、社媒、SEO、邮件），通过 Notion、Slack 协作干活。

听起来很酷。但有个问题——**它的聊天入口是 Slack**。

国内谁用 Slack 啊？我想要的是飞书：我每天在飞书里上班，在飞书里 @ 一下机器人就能派活，这才是顺手的姿势。

于是，一场「把 AI 团队搬进飞书」的改造开始了。
![](https://gitee.com/da-qiang-classmate/typora/raw/master/image/20260805062318100.webp)


### 02.改造成本
**先说顺利的部分：**

- **部署**：模板一键部署到 Vercel，本地 `git clone` + `pnpm install` 就绪
- **接 DeepSeek**：默认的 Claude 换成 DeepSeek 官方 API，写个 `model.ts` 统一配置，6 个智能体一次替换。成本从「每任务几毛钱」降到「几分钱」
- **权限打通**：飞书开放平台建应用、开机器人能力、订阅消息事件，用 lark-cli 一步步验证

**然后是四个差点把我劝退的坑：**

**坑 1：飞书官方适配器，跟 eve 根本不兼容**

飞书官方出了 eve 的适配器，满心欢喜装上——结果消息能收，回复发不出去。

查源码才发现：适配器是 WebSocket 长连接模式，而 eve 的回复机制只在 HTTP webhook 上下文里可用。**这是架构级不兼容，改配置救不了。**

解法：放弃适配器，用 eve 原生 `defineChannel` 自己写了个飞书通道（约 100 行）。webhook 收消息、飞书 API 回复。消息链路瞬间全通。

![](https://gitee.com/da-qiang-classmate/typora/raw/master/image/20260805062455344.webp)

**坑 2：海外域名，国内网络直连不了**

飞书后台配 webhook 时，永远「3 秒超时」。

折腾半天才发现：**飞书服务器在大陆，直连海外托管域名（vercel.app）会超时**。我本机能访问是因为本地网络环境不同；飞书服务器是直连的，够不着。

解法：把挂在 Cloudflare 的域名 `bot.kyjl97.github.io` 绑定到 Vercel，国内流量走 Cloudflare 节点，直连 0.9 秒响应，问题解决。

![](https://gitee.com/da-qiang-classmate/typora/raw/master/image/20260805062611907.webp)

**坑 3：Vercel 部署保护，把 webhook 拦了**

域名通了，webhook 又返回 401。

Vercel 的「部署保护」默认拦截所有外部请求。得去控制台关掉 Vercel Authentication，飞书才把消息送进来。

**坑 4：冷启动超过飞书 3 秒限制**

飞书要求 webhook 3 秒内响应，eve 的 serverless 冷启动要好几秒。

解法：`vercel.json` 里开 Fluid Compute（函数常驻），冷启动降到 0.9 秒。
![](https://gitee.com/da-qiang-classmate/typora/raw/master/image/20260805063007727.webp)

### 03.团队扩充

跑通之后，我发现团队还缺很多角色：选题、调研、核查、审稿、排版……

eve 的机制是「目录即角色」——加一个角色就是加一个目录。我一口气加了 8 个内容工作室成员 + 1 个短视频脚本专家：

![](https://gitee.com/da-qiang-classmate/typora/raw/master/image/20260805054730931.webp)

**一个小彩蛋**：调研专家（张素材）还配了一台「云端浏览器」——普通抓取（web_fetch）打不开的页面，比如纯 JS 渲染的 SPA、需要登录的后台，它会调起 Vercel 的云端浏览器（remote-agent-browser）像真人一样打开网页、拿到内容再回来。一次调研用完即销毁沙箱，不占本地内存、不留数据。

### 04.使用示例

在飞书里 @ 机器人，说一句：

> 「写一篇关于普通人用 AI 提效的文章。先让选题策划出 3 个角度，我选一个后交给调研专家收集素材，然后写手成稿、事实核查、主编定稿、排版成公众号格式，最后归档到 Notion。」

主管会把任务拆给对应专家，产出通过 Notion 流转，最后成品直接出现在知识库里。


或者直接叫某个专家：

> 「把这篇 Notion 文章改写成 1 分钟短视频口播脚本，工具分享类，结尾引导评论扣『提示词』」

短视频专家会输出四段结构（钩子+痛点 → 方法 → 原理 → 动态收尾）、220-260 字的逐字稿，照着念就能录。

还能直接发公众号草稿箱：

> 「把这篇 Notion 文章排版成公众号格式，发布到我的公众号草稿箱，标题『xxx』，封面用这张图 <图片链接>」

社媒协调员会自动转 HTML → 上传封面 → 调微信官方 API 存进草稿箱（**不直接群发**），你在公众号后台确认后点发布——自动排版、人工把关，既省事又合规。

**DeepSeek 不会生图？没关系**——写手和排版设计师都配了 `generate_image` 工具，需要配图时直接调 GPT-Image-2（APIMART）：

> 「写一篇关于 AI 提效的文章，配一张 16:9 封面图，风格：温暖科技、蓝色渐变、一个人和 AI 助手并肩工作」

团队会先写完文章，再按你的要求生成封面/配图，图片 URL 随文交付。


**成本**：很多人以为 14 个 AI 员工很贵，实际算下来几乎可以忽略：

![](https://gitee.com/da-qiang-classmate/typora/raw/master/image/20260805064326098.webp)


**合计：日常使用一天几毛钱封顶**，14 个 AI 员工，比雇一个人便宜无数倍。超出免费额度也只是暂停服务，不会自动扣费。

**最大的收获**：AI Agent 正在从「聊天窗口」变成「真能干活的组织」。而 eve 这类框架的出现，让「组建 AI 团队」从写代码变成了**搭积木**——加一个角色就是加一个目录，接一个平台就是写一个通道。

今天你有几个 AI 员工？也许明天，你的团队会比公司的人都多。
