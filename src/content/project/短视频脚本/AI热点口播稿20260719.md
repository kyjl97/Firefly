### 1. ChatGPT Work
```
Chat G PT Work真正厉害的地方，不是多了一个聊天框
#ChatGPTWork #AI工具 #AI工作流 #远程服务 #小团队
```

```
今天OpenAI的人负责人发了一个很有代表性的用法：他直接对GPT Work口述，让它从大量私信里筛出提到某个项目的人，整理成表格，加上链接，分类，再给每个人的工作流成熟度打分。

这件事表面上看是AI帮你做表格，实际上更重要的是：AI开始从“回答问题”变成“接住一段真实工作”。

普通人最容易忽略的地方就在这里。你不是给它一句prompt就结束了，你要先讲清楚资料在哪里，字段怎么定义，什么叫高质量，最后输出到哪里，哪些步骤不能自动做。

所以GPT Work这种工具，真正的门槛不是会不会聊天，而是你有没有一套能被AI接手的工作流。

比如客户咨询整理、选题归类、邮件处理、资料摘要、表格生成、网站内容更新，这些都不是单点功能，而是一条流程。

如果你现在已经在用GPT、Claude、Codex，但感觉它们很散、串不起来，先别急着继续买课。更应该做的是把你每天重复做的3个任务拆出来，看哪些能交给AI，哪些需要配置，哪些必须保留人工确认。
```

### 2. 个人AI测试集
```
别再问哪个模型最强，先做你的个人AI测试集
#AI模型 #ChatGPT #Claude #Gemini #AI顾问
```

```
今天Zara Zhang提到一个很实用的建议：每个人都应该有自己的personal eval set，也就是用几个和你真实工作生活有关的任务，去测试AI模型到底好不好用。

我觉得这比看排行榜更有价值。

因为排行榜上的任务，不一定是你的任务。你真正关心的可能是：能不能帮我整理Obsidian笔记，能不能改我的网站，能不能把客户问题变成方案，能不能写出像我自己的短视频口播稿。

这些东西不是一句“某某模型最强”能解决的。

更实际的做法是准备5到10个固定测试题。比如一篇你的旧文章、一段客户咨询、一份项目需求、一个报错截图、一组零散笔记。每次换模型、换会员、换工具，都用同一组任务测试。

这样你很快就会知道：哪个模型适合写作，哪个适合代码，哪个适合资料整理，哪个看起来聪明但不稳定。

AI工具选型不要凭热闹。对个人创作者和小团队来说，最省钱的方式不是买最贵的，而是知道自己的任务到底该交给谁。
```

### 3. ChatGPT Sites
```
个人网站以后不只是展示页，而是你的小工具入口
#个人网站 #ChatGPTSites #AI网站 #作品集 #个人IP
```

```
Peter Yang今天发了一个小例子，他和孩子用ChatGPT Site做了一个练乘法的小网站，还用了ChatGPT Images生成界面和角色，加了音乐和关卡。

这个案例本身不复杂，但它代表了一个趋势：个人网站会从“介绍我是谁”，慢慢变成“运行我的东西”。

以前很多人搭个人主页，就是放头像、简介、作品链接、联系方式。现在更值得做的是，把你的知识、服务、作品、工具都放进去。

比如你是创作者，可以做一个选题库入口。你是咨询师，可以做一个服务说明和预约页。你有Obsidian知识库，可以同步成一个可搜索的网站。你有一套小工具，也可以做成一个在线demo。

这类网站不一定一开始就做得很大。先做一个能打开、能展示、能让别人理解你服务的页面，就已经比只发朋友圈强很多。

AI降低的是建站门槛，但真正值钱的是你知道网站要承接什么：作品、信任、搜索流量，还是咨询线索。
```

### 4. AI服务商机会
```
AI落地的机会，不在模型公司手里全部拿走
#AIAgent #AI服务 #工作流 #小团队 #Skill定制
```

```
Aaron Levie今天讲了一个很重要的判断：AI的价值不会只集中在少数模型公司，真正落地会需要大量应用公司、基础设施、路由层、治理工具，以及能推动业务改变的服务商。

这句话翻译成人话就是：模型越来越强，但大多数人还是不知道怎么把它用进自己的工作。

这就是普通人和小团队真正卡住的地方。

他们不是不知道ChatGPT，也不是没听过Claude和Gemini。他们的问题通常更具体：账号怎么配，API怎么接，资料怎么整理，Obsidian怎么和网站打通，AI能不能帮我处理客户咨询，能不能自动生成内容，能不能把重复工作固定下来。

这些需求都不是一个模型发布会能解决的。它需要有人把业务语言翻译成工具动作，把一堆分散工具整理成能跑的流程。

所以以后AI服务不会只剩下“卖账号”和“教prompt”。真正有价值的是帮人搭环境、拆流程、做Skill、做网站、做知识库、做长期维护。

AI越普及，越需要懂落地的人。
```

### 5. 模型安全与成本
```
同一个任务，不同模型的结果可能差很多
#AI模型 #API #AI安全 #Kimi #Claude
```

```
今天Vercel的Guillermo Rauch提到，他们内部做了一些cybersecurity eval，发现Kimi K3、Sol、Fable在能力、成本和拒答上差异很明显。

普通用户不一定要关心这些模型的安全测试细节，但要关心背后的结论：同一个任务，换一个模型，结果可能完全不一样。

有的模型便宜但不够稳，有的模型能力强但成本高，有的模型安全边界很严格，动不动就拒答。你如果只是写一段文案，问题不大；但如果你要让AI改代码、连API、处理文件、做自动化，这些差异就会直接影响结果。

所以现在选AI工具，不能只问“哪个最强”。更应该问：我的任务是什么，能不能出错，资料有没有隐私，预算是多少，失败以后怎么验证。

比如写口播稿、整理资料、生成选题，可以用一套方案；排查代码、部署网站、接API，就要更谨慎，最好有环境隔离和验证步骤。

AI模型越来越多，真正难的是把任务分配清楚。
```

### 6. Obsidian和个人语料
```
AI写得不像你，不一定是模型问题
#Obsidian #AI写作 #知识库 #个人IP #AISkill
```

```
今天还讲到一个现象：AI很擅长很多经济任务，但它很难真正替代“你自己”。尤其是写作，很多AI内容一看就很机械。

这点对内容创作者特别重要。

很多人一开始用AI写内容，会拼命调prompt，要求更口语、更有网感、更像真人。但如果AI根本不了解你的表达方式、服务经验、客户问题和判断标准，它当然只能写出一堆通用话。

所以我一直觉得，AI写作真正该补的不是更多prompt，而是个人语料和知识库。

比如把你过去的文章、口播稿、咨询记录、服务复盘、客户常见问题，都用固定格式放进Obsidian。每条内容有主题、场景、观点、服务承接和例子。这样AI才有东西可以参考。

AI不是替你变成另一个人，而是帮你更稳定地表达你已经知道的东西。

如果你的知识库很乱，AI写出来就会散。如果你的输入有结构，它才可能持续产出像你的内容。
```

### 7. AEO内容自动化
```
个人网站下一步，不只是SEO，还要考虑AI怎么引用你
#AEO #SEO #个人网站 #内容自动化 #AI工作流
```

```
Swyx今天提到，AEO可能会给他带来很大的收入。AEO简单理解，就是不只让搜索引擎找到你，也要让AI搜索、AI问答、AI助手更容易理解和引用你的内容。

这对个人创作者其实很现实。

以前做内容，大家想的是标题、关键词、搜索排名。现在还要多想一步：当别人问AI“谁能帮我搭Obsidian知识库”“谁能帮我配置Claude Code”“个人网站怎么搭”，AI能不能从你的内容里识别出你是相关的人。

这就要求你的网站和文章不能只是情绪表达，要有清楚的服务说明、问题场景、案例、步骤和关键词。

如果你用Obsidian写作，完全可以做一个小自动化：每周让AI检查你的文章标题、标签、内部链接、服务入口和常见问题，然后生成一份优化清单。

个人网站不是搭完就结束。真正有用的网站，是能持续被搜索、被AI理解、被潜在客户找到。
```

### 8. 懂业务也懂AI
```
小团队AI落地，最缺的是翻译官
#AI落地 #小团队 #AI顾问 #工作流 #Agent
```

```
Zara Zhang今天说，企业AI落地最大的障碍，是懂AI的人不懂业务，懂业务的人不懂AI。

这句话放到个人创作者和小团队身上也一样。

很多老板很清楚自己哪里忙：每天要整理资料、回复客户、写内容、做表格、维护网站、处理账号和工具问题。但他说不出来这些任务怎么交给AI。

另一边，很多懂工具的人会讲模型、API、MCP、Agent，但如果不了解真实业务，就很容易做出看起来很酷、实际没人用的东西。

真正能落地的AI方案，中间需要一个翻译过程：把人的工作语言，拆成AI能执行的步骤；把工具能力，翻译成业务能看懂的结果。

所以小团队做AI，不要一上来追求全自动。先选一个最痛的流程，比如客户咨询整理、内容选题生成、Obsidian资料归档、个人网站更新。跑通一个闭环，再扩展第二个。

AI落地不是炫技，是把重复工作变少，把关键判断留下。
```
