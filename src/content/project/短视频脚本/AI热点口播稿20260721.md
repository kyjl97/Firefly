```
今天 Aaron Levie 分享了 Cursor 最新研究的一个发现：用一个强模型做规划和拆解，再用便宜模型去执行具体任务，整个项目的 token 消耗能降低 15 倍。

但问题是，大多数人用 AI 工具时根本没想过这件事。要么全用同一个模型，要么看到新模型就换，没有按任务类型做路由设计。

这也是模型 API 配置、AI Gateway 设计越来越重要的原因。如果你的 AI 工具已经跑起来了，但 token 费用在悄悄涨，先看的不是哪个模型更便宜，而是你的工作流里每一步到底需不需要那么强的智能。

搞清楚这件事，比换模型重要得多。`n`n如果你已经搭了多模型工作流但经常出问题，比如模型切换后输出格式变了、API 调用报错、token 计费对不上，这些排错和配置调整其实都有固定套路。
```

### 7. AI面试的两轮测试
```
AI时代招人，一轮不能用AI，一轮必须用AI
#AI工作流 #小团队 #Skill定制 #Agent #AI工具选型
```

```
今天 Zara Zhang 提了一个很实用的 AI 时代招聘思路：面试分两轮。第一轮面对面、禁止用 AI，纯测领域知识和临场判断。第二轮给一个必须用 AI 才能完成的项目，评估的不只是结果，还有候选人和 Agent 的对话记录。

这个思路不只适用于招人，它其实揭示了一个更深层的问题：AI 时代，人和工具的协作质量才是真正的竞争力。

很多人用 AI 工具，只看最终结果。生成了一篇文章、做了一个页面、写了一段代码，觉得能用就行。但过程中的指令质量、判断力、对边界的理解，决定了产出是否稳定可靠。

这也解释了为什么同一个 AI 工具，不同人用出来的效果差距这么大。不是模型不行，是使用方式没有系统化。

对小团队来说，这意味着你不需要招一堆 AI 专家，但需要让团队里每个人都知道：什么任务交给 AI、怎么写清楚指令、什么时候自己接手、失败了怎么排查。

这就是工作流设计和 Skill 定制的真正意义。它不是一个人的 prompt 技巧，而是整个团队的协作规范。

如果你想把 AI 能力真正沉淀到团队里，与其培训"怎么用 ChatGPT"，不如先梳理：哪些任务有重复规则、哪些判断可以标准化、哪些流程可以交给 Agent 执行。
```
