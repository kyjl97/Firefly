### 2. Codex 长任务别只怪模型笨

[https://x.com/thsottiaux/status/2082609662231502932](https://x.com/thsottiaux/status/2082609662231502932)

```
AI Agent做长任务失败，先查上下文
#Codex #ClaudeCode #上下文配置 #工作目录 #远程排错
```

```
很多人用 agent做长任务，做到一半就开始胡说、漏文件、忘记前面的要求，然后第一反应是模型不行。分享下我自己的实战经验：模型要跑复杂任务，得允许它跨多个上下文工作，还要有可靠的压缩和任务记录。翻译成普通话就是：你不能只丢一句“帮我改项目”，然后指望它永远记得所有细节。先把 AGENTS 规则、目标文件、验收标准和禁止操作写清楚；任务长了，就让它阶段性总结当前状态。新手还要先确认工作目录选对了、依赖装好了、测试命令能跑，并且每一步都留下结果。很多所谓 AI 编程失败，本质不是写代码差，而是工作目录、规则文件和上下文管理没配好。
```

### 3. 做页面前先让 AI 问清楚

[https://x.com/petergyang/status/2082579428090192192](https://x.com/petergyang/status/2082579428090192192)

```
AI 做网站，第一步不是让它开写
#个人网站 #ClaudeCode #需求整理 #设计规则 #网站搭建
```

```
如果你想让 AI 帮你做个人网站、服务页或者小工具页面，不要第一句就说“帮我做一个高级一点的页面”。今天有人分享 Claude Design 一个好用的地方：它会先问清楚需求，再开始生成。这个习惯特别适合普通用户。你可以先准备一份很简单的说明：这个页面给谁看，要突出什么服务，需要哪些栏目，颜色和字体有没有参考，最后怎么验证能用。很多网站做出来不好看，不是 AI 不会写，而是前面没有需求边界。做个人网站交付时，我更看重这一步：先把目标、素材、栏目和部署方式说清楚，再让 agent 动手。先问清楚，后面改样式、补内容、上线排错，才不会反复推倒重来，也更省沟通时间。
```

### 4. ChatGPT 语音好用，但要接得住
来源：Every CEO Dan Shipper 分享团队对 ChatGPT for Work 语音模式的使用反馈
[https://x.com/danshipper/status/2082613916706693560](https://x.com/danshipper/status/2082613916706693560)

```
语音聊 AI 前，先看工具有没有接好
#ChatGPTWork #工具连接 #账号配置 #工作流顾问 #远程配置
```

```
现在很多人开始觉得 ChatGPT 的语音模式很好用，因为不用打字，直接说想法就能让 AI 帮你整理。但这里有个普通用户很容易忽略的点：语音只是入口，不是完整工作流。你说完以后，它能不能找到你的文件？能不能写进文档？能不能调用浏览器、日历、邮件或者项目目录？如果这些权限和工具没接好，语音再自然，也只是陪你聊天。第一次配置这类功能，先别追求炫酷，先检查账号是不是对应工作空间，工具连接是否授权，输出结果保存在哪里。还要确认手机端和电脑端是不是同一个环境，不然你口头安排的任务，最后可能根本落不到本地文件里。把这些基础打通，语音才可能真的帮你少做重复操作。
```

### 5. 别让 AI 偷偷替你改文件
来源：AI 教程作者 Peter Yang 复盘使用 AI 后出现的三个效率暗坑
[https://x.com/petergyang/status/2082642205811106158](https://x.com/petergyang/status/2082642205811106158)

```
AI 很勤快，你也要会验收
#AI排错 #文件备份 #Codex #Review流程 #工作流搭建
```

```
今天有个提醒很适合所有刚开始用 Agent 的人：AI 会让你变快，也会让你变懒。最危险的不是它回答错，而是你根本没看它改了什么。很多人让 Codex 或 Claude Code 处理文件，看到终端跑完就以为好了，结果旧内容被覆盖、格式乱了、链接断了，过几天才发现。我的建议是，凡是让 AI 改本地文件，先固定三步：第一，确认它只能改目标目录；第二，改完让它列出变化；第三，用预览、测试或 Git diff 做验收。不会看差异也没关系，至少要保留原文件和备份。做 Obsidian 知识库、脚本或网站时尤其要这样，因为文件多了以后，错误不一定马上暴露。能截图就截图，能备份就备份。AI 可以帮你动手，但交付前的检查不能省。
```

### 8. 手机上的 Agent 也要有边界
来源：Cursor 设计成员 Ryo Lu 宣布 Cursor iOS 可在手机上使用 agents
[https://x.com/ryolu_/status/2082539893729972320](https://x.com/ryolu_/status/2082539893729972320)

```
手机指挥 Agent，不等于随便改项目
#Cursor #Agent配置 #代码托管 #权限检查 #远程协助
```

```
Cursor iOS 开始把 Agent 放到手机上，这个方向很有意思：以后你在外面也能给项目下指令。但普通人别把它理解成“手机点两下，项目自动好了”。真正的问题是，手机上的 Agent 连接的是哪个仓库？有没有权限改代码？改完以后谁来测试？出了问题怎么回滚？如果你只是临时让它改一句文案还好，涉及配置文件、支付接口、网站部署，就必须有更清楚的流程。移动端 Agent 更适合做轻量反馈、任务排队和结果查看，不适合在没有检查的情况下直接改生产项目。尤其是个人网站和客户项目，至少要有分支、备份和预览地址。先把仓库权限、测试命令和备份机制配好，再谈随时随地办公。
```
