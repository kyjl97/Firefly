### 1. Claude 权限别全开
来源：Anthropic Engineering 复盘 Claude 在不同产品里的沙箱、文件权限、MCP 和数据外传边界
[https://www.anthropic.com/engineering/how-we-contain-claude](https://www.anthropic.com/engineering/how-we-contain-claude)

```
Claude Code 权限别一把梭
#ClaudeCode #Agent权限 #MCP #环境配置 #远程排错
```

```
Anthropic 今天讲了一个很现实的问题：Agent 越能干，越不能随便给它所有权限。很多人装 Claude Code 或 Codex，第一步就卡在“要不要允许读写文件、能不能联网、MCP 能不能开”。不要一上来全点允许。先分清三件事：哪些目录只读，哪些目录可以改，哪些文件绝对不要碰，比如密钥、账号配置和真实客户资料。测试新工具时，用一个空项目或复制出来的文件夹先跑，不要直接连正式 Obsidian 仓库和网站源码。再检查有没有备份、Git 记录和删除保护，出问题至少能退回来。远程配置时我也会先做权限边界，因为真正危险的不是 Agent 不会干活，而是它太愿意帮忙，结果把不该读、不该传、不该改的东西也处理了。
```

### 2. Agent 修问题先补上下文
来源：Linear 产品负责人 Nan Yu 分享 Issue 留评论、补充上下文后 Agent 继续推进的工作流
[https://x.com/thenanyu/status/2083534333428580501](https://x.com/thenanyu/status/2083534333428580501)

```
别只丢一句“帮我修”
#Agent #Codex #ClaudeCode #报错排查 #工作流搭建
```

```
Linear 这个例子提醒我，Agent 修问题不是魔法，它最需要的是上下文。很多人找我远程排错时，只说“打不开”“一直报错”“帮我修一下”，但少了系统版本、软件版本、项目路径、最后一步操作和完整报错，Codex 或 Claude Code 也只能猜。你可以先做一个最小记录：我想完成什么，我在哪一步失败，错误原文是什么，重启或换网络后有没有变化。如果是网站或代码问题，再加上最近改了哪个文件。最好把截图、日志和复现步骤放在同一个文件夹里，方便复查。上下文补齐以后，Agent 才能继续往下查，而不是反复问同样的问题。真正好用的工作流，是先把问题写成能复现、能验证的小任务，再让工具动手。
```

### 3. Skill 做成插件也会卡
来源：Peter Yang 反馈把一个去除 AI 味的 Skill 打包成插件时遇到影响用户体验的 bug
[https://x.com/petergyang/status/2083594381748302160](https://x.com/petergyang/status/2083594381748302160)

```
Skill 能用，不等于好交付
#Skill定制 #插件配置 #Codex #ClaudeCode #安装排错
```

```
今天有个很小但很真实的信号：一个 Skill 自己能跑，不代表打包成插件后普通用户就能顺利用。很多人做自动化也是这样，在自己电脑上命令能执行，一交给别人就开始出问题：路径不一样，权限不一样，依赖没装，按钮说明不清楚，甚至安装完不知道从哪里启动。所以做 Skill 定制或插件交付时，不能只看作者电脑上跑通。至少要检查安装入口、首次启动、配置文件、报错提示和卸载边界。用户真正买的不是一段提示词，而是“我照着做能不能用起来”。如果你准备把自己的写作、整理、发布流程封装成 Skill，先把使用说明和失败处理写清楚，比多加十个功能更重要。
```

### 4. Agent CRM 要先会部署
来源：Vercel CEO Guillermo Rauch 转发开源 Agent CRM，强调它可自托管、可无服务器部署、多渠道且不绑定模型
[https://x.com/rauchg/status/2083684679362965605](https://x.com/rauchg/status/2083684679362965605)

```
想用 AI 管客户，先别急着接单
#个人网站 #CRM #API配置 #部署排错 #AI工作流
```

```
今天看到一个开源 Agent CRM，很容易让小团队心动：好像装上以后，客户消息、线索跟进、自动回复都能交给 AI。但普通人最容易卡的不是功能介绍，而是部署和数据入口。你先问自己：要放在自己服务器，还是用网站平台部署？客户数据从哪里进来？API 密钥谁保管？自动回复失败以后谁接手？如果这些没想清楚，CRM 只会变成另一个没人维护的软件。小团队更适合先跑一个低风险流程，比如只整理咨询记录，不直接自动回复客户。等账号、域名、数据库和费用边界都清楚，再逐步接入 Agent。我做个人网站和工作流搭建时，也会先把“能稳定部署、能备份、能回滚”放在功能前面。
```

### 5. 长任务先设预算和验收
来源：Andrej Karpathy 用 Opus 5 做长时间三维网页生成实验，并提到 100 万 token 预算和模型难以自己检查视频效果
[https://x.com/karpathy/status/2083749667410727319](https://x.com/karpathy/status/2083749667410727319)

```
AI 能跑很久，也会跑偏很久
#AI工具 #token预算 #Codex #项目验收 #远程排错
```

```
Karpathy 这个长任务实验很有意思，但对普通用户的提醒很简单：AI 能连续干两小时，不代表结果一定可用。你让 Codex 或 Claude Code 写网站、做动画、整理大量资料时，先别直接丢一个超大任务。先设预算和验收点，比如最多跑多久、最多改哪些文件、每一步要产出什么、结果怎么打开检查。特别是视频、网页、图片和交互类任务，AI 经常写了很多代码，却没真正看懂页面效果。你要保留截图、预览地址和回滚方式，最好先让它做一个小样，再扩展到完整项目。很多成本不是模型贵，而是任务跑偏后你还要花时间补救。远程协助这类项目时，我会先把任务拆小，让每一步都有可见结果，再决定要不要继续加深。
```

### 6. Agent 接设备要先控权限
来源：Peter Steinberger 分享给 Agent 摄像头权限来端到端测试硬件语音唤醒命令的实验
[https://x.com/steipete/status/2083694161933594703](https://x.com/steipete/status/2083694161933594703)

```
Agent 能看屏幕，更要管边界
#Agent #浏览器权限 #设备权限 #Windows配置 #远程排错
```

```
今天有人把 Agent 接到摄像头，用来测试硬件语音唤醒。这个场景对多数人不一定马上用到，但提醒很具体：以后 Agent 会越来越多地接浏览器、麦克风、摄像头、桌面和本地软件。你可能会遇到授权弹窗、驱动异常、浏览器扩展冲突、Windows 隐私权限没开，或者开了以后不知道怎么关。不要为了省事把所有权限长期打开。先用临时测试窗口，确认它只访问这次任务需要的内容；测试完关掉权限，并记录改过哪些设置。如果客户电脑里还有会议软件、录屏工具或远程控制软件，更要逐项排查。远程排错时，设备权限、浏览器权限和杀毒软件拦截经常混在一起。先把边界列出来，比反复重装软件更快。
```

### 7. 业务 Agent 先写清 SOP
来源：No Priors 访谈 Netic 创始人，讨论 AI Agent 如何处理家政维修、预约、客服和真实业务规则
[https://www.youtube.com/watch?v=wWbX3NL6_Uo](https://www.youtube.com/watch?v=wWbX3NL6_Uo)

```
小团队上 Agent，先别替人做决定
#Agent #业务流程 #客服自动化 #Skill定制 #顾问服务
```

```
这期播客讲的是 AI Agent 进入真实服务行业，比如维修、预约和客户接待。普通小团队听完不要先想“我也要一个全自动客服”，先想你的规则有没有写清楚。客户来咨询时，哪些问题可以自动回答，哪些必须转人工，报价前要问哪些信息，紧急情况怎么处理，谁有权限改订单，这些都比模型选择更重要。如果 SOP 没有，Agent 只会把混乱放大。你可以先从一个很窄的流程开始，比如收集客户电脑系统、报错截图、软件版本和期望结果，再交给人判断。这样既能省沟通时间，也不会让 AI 乱承诺。做工作流顾问和 Skill 定制时，我最先整理的就是这些边界，而不是一上来接所有平台。
```
