Peter Yang 今天提到一个细节：有些 Agent 会自己检查 Skill 和记忆，把没用、重复、低质量的东西清掉。这个点对普通用户很有关系。很多人装了 Claude Code、Codex、Obsidian 插件和一堆 Skill，刚开始觉得很强，过几周就乱了：同一个命令有三种写法，旧路径还在，过期 API 密钥没人删，Agent 读到旧规则还会照着做。不要等出错了才整理。你可以每周检查一次：哪些 Skill 真的用过，哪些规则互相冲突，哪些记忆已经过期，哪些文件不该再让 Agent 读取。特别是换电脑、换模型、换工作目录以后，更要重新验证一遍。做 Skill 定制时，我不会只交一个能跑的提示词，还会把清理、更新和验证规则写进去，不然工作流越用越重，最后反而拖慢自己。
```

#Agent #Skill #工作流搭建 #团队配置 #顾问服务
```

```
Vercel 今天讲了一个大团队的问题：每个人都在建 Agent，最后入口太多，体验反而变差。普通人和小团队也会遇到同样的小版本：装了 ChatGPT、Claude Code、Codex、浏览器插件、Obsidian 插件，每个都能干一点事，但你不知道该从哪里开始。先别继续装新工具，先收入口。把任务分成几类：写作整理进 Obsidian，代码和网站交给 Codex 或 Claude Code，账号和 API 配置单独记录，重复流程再做成 Skill。这样你遇到问题时，知道去哪个工作目录、哪份规则、哪组权限里查，也知道哪一步需要人工确认。最好再写一张入口表，放清楚每个工具负责什么。做个人 AI 工作台时，我更看重入口清楚，而不是工具数量多。入口乱了，后面排错、交接和升级都会变得很费时间。
```

### 4. AI 任务要能验收
来源：Box CEO Aaron Levie 讨论代码、数学等任务容易被自动化，是因为结果更容易被客观测试
[https://x.com/levie/status/2083965372747882741](https://x.com/levie/status/2083965372747882741)

```
让 AI 干活前先写验收
#AI工作流 #Codex #ClaudeCode #测试验证 #远程排错
```

```
Aaron Levie 今天说了一个很关键的差别：代码、数学这类任务更容易自动化，因为结果能测试。普通人用 AI 也要记住这一点。你让 Codex 改网站、让 Claude Code 整理资料、让 Agent 写文章，不能只说“帮我做好”。先写验收标准：网站能不能打开，按钮能不能点，命令能不能复制，Obsidian 链接有没有断，正文有没有乱码，API 有没有真实跑通。越是没有标准答案的任务，越要提前规定怎么检查。否则 AI 看起来做了很多，最后你还是不知道能不能交付。远程做配置或工作流搭建时，我会先把可验证目标列出来，再让 Agent 执行，最后按清单逐项复查。不是为了复杂，而是为了避免做完一堆文件，却没有一个结果能放心使用。
```

### 6. AI 接管后人更要定边界
来源：Dan Shipper 讨论当语言模型接手原本由人完成的任务时，人需要重新看见自己的流程和把关角色
[https://x.com/danshipper/status/2084038453831020916](https://x.com/danshipper/status/2084038453831020916)

```
AI 做得越多，你越要会交代
#AI工作流 #Agent #Obsidian #内容生产 #顾问服务
```

```
Dan Shipper 今天讲到一个感受：AI 接手了你原来一步步做的任务，人会突然不知道自己还负责什么。普通人不用纠结这个概念，先看具体操作。比如你让 AI 帮你写文章、整理资料、改网站、处理客户咨询，它确实能省很多重复劳动，但你仍然要决定资料从哪里来、哪些内容不能乱说、结果放到哪里、谁来复查、失败了怎么退回。很多人卡在“工具会用了，但流程没变”，最后变成每天反复改 AI 的输出。先把自己的 Obsidian 素材、写作模板、发布路径和检查清单理顺，再让 Agent 接进去，必要时先只接一个小环节。工作流顾问真正做的不是让 AI 替你一切，而是把人该判断的边界留下，把机器适合重复的部分接稳。
```
